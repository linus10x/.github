# Contributing

Thanks for taking the time to help.

## Before you start

- Check open issues and pull requests to avoid duplicate work.
- For anything larger than a small fix, open an issue first so the approach can be agreed.

## Making a change

1. Fork the repository and create a branch from `main`.
2. Keep each pull request to one logical change.
3. Add or update tests for the behavior you change.
4. Run the repository's checks locally before you push.
5. Fill in the pull request template.

## Standards

- Never commit secrets, credentials, personal data or files over 1 MB.
- Use synthetic data in samples and tests.
- Write commit messages in the imperative mood ("Add retry to fetch").

## Review

Every pull request needs green CI and an approving review before it merges. Maintainers may squash commits on merge.
